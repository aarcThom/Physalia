ComponentTransmitter (`Components/Serializers/ComponentTransmitter.cs`, namespace `Physalia.GH.Components`, GUID 4BA76257-AD4C-462C-AB7E-B130DB176BF4) — built 2026-06-13. The canvas-building analog of PyTransmitter: a `RoutingComponentBase<string>` that takes an LLM-generated **GhJSON graph as the consumed signal's payload**, places the whole graph on the canvas, waits for it to solve, then routes the GhJSON forward on Success or a problem description back on Fail (agentic fix loop for whole-graph generation).

Key design (decisions locked with user):
- **Input = signal payload** (`TryGetData = signal.Payload`); on success the same GhJSON is echoed forward.
- **Delete-then-replace**: tracks placed InstanceGuids in `_placedGuids`, removes them (`doc.RemoveObject`) before each new placement.
- **Failure = error-level RuntimeMessages only**, PLUS a structural **orphan wiring check**: a placed `IGH_Component` (floating `IGH_Param`s exempt) whose pivot.X > minPlacedX + 30f (LeftColumnTolerance) and that has inputs all with `SourceCount == 0` is flagged as disconnected.
- **Async pattern**: `AutoScheduleRead => false`. `PushSolve` validates + subscribes `RhinoApp.Idle` (Put mutates doc + triggers own NewSolution, can't run in SolveInstance). `OnIdlePlace` removes old, calls `GhJsonBridge.LoadAndPlaceJson`, records GUIDs, then `RequestReadPass()`. `IsReadReady` gates on every placed `IGH_ActiveObject.Phase` being past Blank/Computing (generalizes PyTransmitter's HasComputed; base's retry loop drives the placed graph to solve).

Bridge change (`Generation/GhJsonBridge.cs`): `PlaceResult` gained `IReadOnlyList<Guid> PlacedGuids`; refactored core into private `PlaceDocument(GhJsonDocument, PointF)`; added `LoadAndPlaceJson(json, origin)` (uses `GhJson.FromJson`) alongside the existing file-path `LoadAndPlace`. Additive — Deserializer unchanged.

Builds clean (0 errors). Manual Rhino verification (happy/error/orphan/replace paths) not yet run. Related: [[gh-apikey-goo]] sibling pattern; see PyTransmitter for the single-script analog.

## Responsibility split with Canvas Observation (2026-06-17) — CompTx = mechanics, Canvas Observation = runtime health
Removed CompTx's runtime checks. **CompTx now reports ONLY mechanical placement** on its Fail: invalid GhJSON, placement failure (`_pushError`), connection-creation failures (`_placeWarnings`), unrepaired structural issues (`_unfixedIssues`). Deleted `CollectRuntimeErrors`, `CollectOrphanComponents`, and `LeftColumnTolerance`; removed the `IsReadReady` phase-poll (CompTx no longer reads runtime, so it needn't wait for placed components to settle — base default `true`).
**Why orphan check was removed:** it flagged any non-source component whose inputs were all unwired (`Params.Input.All(p => p.SourceCount == 0)`), false-positiving on input-optional primitives like XY/XZ/YZ Plane (optional `Origin` left unwired, yet they produce a plane).
**New contract:** CompTx **Success payload = placed components' GUIDs**, newline-separated (`SerializePlacedGuids`), instead of the GhJSON. `Canvas Observation` (`Components/Guardrails/CanvasObservation.cs`) parses those GUIDs and scans **only that placed graph** for: (1) errors, (2) warnings, (3) **dead components** = `IGH_Component` with outputs where `Params.Output.All(p => p.VolatileData.IsEmpty)` (skipped if the component already errored — cascade). Canvas Observation gained an `IsReadReady` phase-poll (copied from CompTx's old one) scoped to those GUIDs, and falls back to a whole-document scan when the payload has no parseable GUIDs (standalone probe). This scoping is what lets Canvas Observation do richer checks without flagging idle Physalia pipeline components. Both build clean (0 errors); Rhino verification pending. Note: `planning/physalia-primitives.md` Canvas Observation spec describes an unrelated viewport-screenshot component (name collision), not this error-scanner.

## LLM graph relayout on placement (2026-07-01) — supersedes "LLM supplies pivot" for the direct path
`GhJsonBridge.LoadAndPlaceJson` (the CompTx / LLM path ONLY) now **recomputes the layout** and overwrites the model's pivots before placing, via new private `RelayoutLlmGraph(doc)`. Reason: the LLM's own pivots pack columns tightly and stack wide source sliders on top of the components they feed (overlap); the arrow also pointed at an empty bounding-box corner. So the earlier "LLM supplies pivot, no layout pass in the direct path" note (section above) is now false — the direct path DOES relayout.
- `RelayoutLlmGraph` builds a raw id-graph (component `Id`s + connection `From.Id→To.Id`) and calls `HierarchicalLayout.ComputePositions(nodeIds, edges)` — a **new core overload** added alongside the existing `ComputePositions(PhySchemaDocument)` (which now just builds ids/edges and delegates). Sugiyama: layer by data-flow depth, **stack nodes vertically within a layer** (this is what stops slider/consumer overlap), barycenter ordering. Pivots are then written back onto each `GhJsonComponent.Pivot` (both `GhJsonComponent.Pivot` and `GhJsonPivot.X/Y` are settable — confirmed via reflection).
- Anchor: HierarchicalLayout puts layer-0's top node at origin `(50,50)`, which equals the bounding-box corner, so `PlaceDocument`'s existing **corner anchoring** (`ComputeOffset`, unchanged) now lands the real upper-left component on the transmitter arrow — no special anchor logic needed. (A short-lived `anchorTopLeftComponent`/`ComputeTopLeftComponentOffset` attempt was added then removed.)
- Tuning knobs: `HierarchicalLayout.LayerSpacing` (horizontal, now 400f) + `NodeSpacing` (vertical, now 120f).
- Scope: ONLY `LoadAndPlaceJson`. Presets (`LoadAndPlaceAnchored`) + Deserializer (`LoadAndPlace` file) still go through `PlaceDocument` with their authored pivots — untouched. Builds clean; live Rhino verify pending. Iterated from a scaling hack (2X general / 4X sliders) that scattered sliders — relayout replaced it.

## Connection wiring fix (2026-06-14) — paramIndex is mandatory
**Root cause of "connections not working":** `ghjson-dotnet` `src/GhJSON.Grasshopper/PutOperations/CanvasPlacer.cs` → `GetParameter` resolves a connection endpoint's param by **paramIndex FIRST, then case-insensitive match against the param's full `.Name`** — NEVER the NickName (floating params like Number Slider/Panel return themselves, so those ends always resolve). Our componentCatalog fed short NickName-style values ("X","Pt") with no index, so any component whose real Name≠NickName (e.g. Construct Point real names "X coordinate"/"Y coordinate"/"Z coordinate", output "Point") failed the name match and the wire was silently dropped (only a `PutResult.Warning`, which Physalia discarded as a count). ghjson-dotnet is a NuGet **PackageReference v1.0.0** (not a project ref), so a library-source change wouldn't reach Physalia without repackaging.
**Fix (schema-only, GhJSON/direct path; PhySchema path has the same bug but left as-is):** GhJSONSchema.json connectionEndpoint now `required: ["id","paramIndex"]` (paramIndex first, paramName optional/readability). paramIndex = zero-based position in the component's OUTPUT list (for `from`) / INPUT list (for `to`), in componentCatalog array order. Rules + catalog description + both examples updated to index every endpoint (mirrors ghjson-spec/examples/simple-addition.ghjson). 
**Diagnostics added so it can't go silent again:** `PlaceResult` gained `IReadOnlyList<string> Warnings` (from `PutResult.Warnings`); ComponentTransmitter caches them (`_placeWarnings`) and `ReadSolve` now Fails/routes feedback when connections fail, with a "Connections that could not be created" section in `BuildFeedback`. Builds clean.
