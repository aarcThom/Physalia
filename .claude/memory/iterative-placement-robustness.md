Fixes landed 2026-07-08 (working tree) after diagnosing the "Placement failed: The GhJSON file contains no components to place." session (export `physalia-chat-20260708-0010.txt` on Desktop):

1. **Component Resolver destroyed ghpatches** (the reported error): `ResolveComponentNames` parsed any payload with `GhJson.FromJson` — a ghpatch binds to a `GhJsonDocument` with `Components = null`, `kind`/`patch` drop, and `ToJson` re-serializes an empty full document that CompTx then rejects with the misleading error. Fix: `ComponentResolver` branches on `GhPatchDetector.IsGhPatch` → new `GhJsonBridge.ResolvePatchComponentNames` resolves only `patch.components.add` (via shared `ResolveComponentList` helper) and re-serializes with `GhJson.PatchToJson`; a patch with no adds passes through byte-identical.
2. **JsonExtractor first-match**: a self-correcting model emitting several ```json blocks in one response had its FIRST (abandoned) attempt placed. Fix: `ExtractJson` collects all fenced blocks and returns the LAST that parses (fallback: nearest earlier parseable block for truncated output, else last outright). Follow-up same day: unfenced text now uses a balanced-brace scan (string-literal aware, steps past unclosed openers) collecting bare `{...}`/`[...]` candidates with the same last-parseable policy — covers multiple bare attempts and stray prose braces; old outermost-span behavior kept as final fallback. 10 new tests in JsonExtractorTests.
3. **Canvas Observation anonymous feedback**: warning/error/dead lines carried only `Name` — five identical "Construct Point: ..." lines, model had to guess. Fix: `Label()` = Name + 'NickName' + (InstanceGuid), matching the canvas-state export identity so the model can patch by instanceGuid; scoped scans also get a sharper header ("The graph from your last response was placed...").
3b. **Canvas Observation delta-only scope on patch turns** (follow-up, same day): CompTx's patch Success payload is only added+modified GUIDs, so cascade breakage in earlier-placed components was never scanned, and a remove-only patch (empty payload) was dropped by TryGetData — no scan at all. Fix: CanvasObservation now ACCUMULATES every GUID ever received (`_watchedGuids`, session-only, cleared in OnCleared, never serialized) and scans the whole watched graph each turn; removed components pruned at scan time; locked ones stay watched but are excluded (they never solve — would jam IsReadReady); blank payload accepted once GUIDs are watched; whole-doc standalone-probe fallback only when nothing is watched.
4. **Preambles** (Node Graph.txt + Python3 Script.txt): added "Emit exactly ONE JSON document per response — never include drafts or abandoned attempts."
5. **Stale base checksum broke the second turn** (follow-up, same day — the "generate a house then cap the roof ends" session): the model reused the pre-placement base checksum on the cap-roof patch → `base_checksum_mismatch`, and then dead-ended ("I don't have the current canvas state in this message"). Two root causes: (a) `CanvasStateGrounder` refreshes async/debounced off `SolutionEnd` and SKIPS the placement's own SolutionEnd (that `NewSolution(false)` runs inside `IsImporting=true`), so it lags the true canvas by a solution — two after a placement — and `ConversationLog` folds that stale grounding when it mints Instructions in the prompt's own solution; (b) the mismatch feedback was error text only, and its "re-read the CURRENT canvas state provided with this message" pointed at the SAME stale grounding channel, so the retry couldn't self-heal. Fix A (`ConversationLog.BuildGroundedSystemPrompt`): explicit `case CanvasStateGrounding` re-exports the live canvas synchronously (`GhJsonBridge.TryExportCanvasState`, the same code path the patch base resolves against) at latch time and folds THAT fresh JSON+checksum — the wire value is ignored for canvas state. Fix B (`GhJsonBridge.Patch.cs` mismatch branch): the refusal Payload now embeds the fresh checksum + full current GhJSON (same "copy this verbatim" wording as the grounding; empty-canvas case tells the model to emit a full document), so a genuine concurrent edit converges in one automatic round-trip. Both are Payload/system-prompt text — carrier discipline holds, no new signal field. Lenient toggle unaffected (skips the branch when `verifyBase=false`).

6. **Spurious ConnectionNotFound + id drift + empty-patch ping-pong** (follow-up, same day — the "traditional american house" session, where the canvas ended up CORRECT but the model was told its ops "did NOT apply"): four fixes. (a) The GhJSON 1.1.1 library's document-level ApplyPatch matches connection removes by paramName; the model wires by id+paramIndex (as instructed), so every name-less remove produced a library ConnectionNotFound conflict even when Physalia's WireConnection (paramIndex-first, the layer that actually mutates the canvas) removed the wire fine — falsely failing the outcome. Fix: library conflicts at `connections.*` are filtered out of the outcome; WireConnection is the single authority for wire conflicts. (b) Export ids were renumbered in insertion order every export, so ids the model remembered from its own earlier patches silently landed wires on WRONG components (PorchMin into a gable Entwine). Fix: session-stable ids — per-document `StableIdRegistry` (instanceGuid→id, assigned once, never reused, weak-keyed) in `GhJsonBridge.CanvasState.cs`; `AssignStableIds` remaps every export (components, connection endpoints, groups+members); patch adds and full placements `RegisterStableIds` so the model's authored ids stick; retired ids never reused, so a stale id resolves to nothing (loud) instead of a different component (silent). Grounding text now states ids are session-stable. (c) An empty patch (no ops) short-circuits as no-op success BEFORE the checksum gate — the model emits one to say "done", and refusing it over its own prior partial-apply's drift trapped the loop in mismatch→regenerate→empty-patch forever. (d) Partial-apply feedback: counts reworded to "canvas components affected" (op-counting made the model reconcile against its patch's op lists and second-guess), and the fresh post-apply checksum is embedded (`CanvasPatchOutcome.PostApplyChecksum`) since a partial apply always stales the model's base.

**Why:** ghpatch mode landed 2026-07-07 but Component Resolver was never made patch-aware — the second turn of every conversation is a ghpatch, so the whole iterative loop was broken. The checksum-staleness follow-up (5) is the same theme one layer up: the loop only works if the grounding the model sees at inference is the state a patch will actually apply against, and a human must be able to edit between turns. Round (6) is the identity layer: feedback must be TRUE (never report an applied op as failed) and ids must be STABLE (a remembered id must never silently mean a different component).

**How to apply:** live Rhino verification still pending: (a) multi-block response places the last block, (b) modify-only ghpatch applies through the full pipeline WITH a Component Catalog wired into the Resolver, (c) feedback lines carry nickname+guid, (d) generate→place→edit-prompt→second patch's base checksum matches with NO mismatch, (e) if a slider is dragged mid-turn to force a mismatch, the feedback carries fresh state and the retry converges, (f) a connections.remove copied verbatim from the grounding applies with NO ConnectionNotFound in the feedback, (g) component ids in the grounding stay identical across three consecutive patch turns, (h) an empty patch routes Success without a mismatch.
