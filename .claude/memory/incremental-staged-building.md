2026-07-27, branch `feat/incremental_nodes`. **Built, builds clean, 325 Core tests pass — NOT yet run in Rhino.** Authoritative doc: `planning/incremental-building.md`.

The model now places a definition in **stages** — one slice per response, measured before the next is authored — instead of writing the whole graph and repairing it. The mechanical blocker was that a clean geometry report on a correct stage 1 is indistinguishable from one on a finished definition, so the report's "matches your intent → reply in prose" handed the model an exit on round one.

**The plan block is prose, not a document field.** The model writes `<plan> goal: … / 1. … / 2. … / now: 2 </plan>` ahead of its JSON. `JsonExtractor` already takes the last JSON block and discards the rest, so it reaches conversation history and never reaches placement. A `buildPlan` property *inside* the GhJSON would have had to survive Physalia's schema, the GhJSON library's schema, AND its deserializer — a rejection there fails a submission for a reason unrelated to the graph. Don't move it inside.

**Pieces:** `Physalia.Core/Planning/` (BuildPlan records + BuildPlanParser: parse + RenderProgress, pure); `Components/ControlFlow/BuildPlanTracker.cs` ("Build Plan" — RoutingComponentBase pass-through tap, `HasFailOutput => false`, extra `Progress` text output written from `OnSolveTick`); Geometry Report detects `BuildPlanParser.DigestMarker` in its Message input and swaps its closing instruction for the digest's staged one. No mode flag — wire the tracker in and the report adapts.

**`now:` never advances on a guess.** A response omitting it leaves the stage put, because the round where that matters is a correction round, which rebuilds the stage it just failed.

**The lint already enforces good staging** — `LintOrphan` rejects a data-only source nothing consumes (so no adding sliders "for the next stage") while exempting geometry terminals (so a stage ending in an unconsumed Domain Box passes). The preamble's "every stage produces geometry and stands alone" is the same rule the code already checks. See [[dead-wire-lint-projected-graph]].
